## Context
The Governor Framework is a framework-agnostic AI agent governance system for controlling tool usage, enforcing policies, and managing compliance across different CLI environments. It was extracted from SovereignAI to become a standalone, reusable framework.

## Current Architecture Overview

The framework has a layered architecture:

**Layer 1 (Entry Point):** `governor.py`
- Main entry point for Devin CLI hook system
- Own logging (isolated to governor.py)
- Imports protocol.py ONLY
- Receives hook events via CLI, routes to handlers
- Error handling with fail-closed/fail-open modes

**Layer 2 (Hook Handlers):** `hook_handlers/`
- `_base.py`: Base handler class
- Specific handlers: session_start, session_end, pre_tool_use, post_tool_use, permission_request, user_prompt_submit, stop, post_compaction
- Each handler implements execute() method with payload, state_machine, engine

**Layer 3 (State Machine):** `state_machine.py`
- Self-contained, no imports from other Governor files
- Phase-based compliance tracking (INIT, EXECUTE, RESEARCH, PLAN, VALIDATE, COMMIT)
- Bypass management (runtime, team, once, session scopes)
- Counter tracking (exec, validate)
- Flag management (research_required)
- Compliance state machine (testing_in_progress, testing_complete, blocked, ready_to_proceed)
- Agent discovery from .devin/agents.json
- File locking for state persistence
- Checksum verification for state integrity

**Layer 4 (Engine):** `engine.py`
- Rule evaluation engine
- Policy enforcement
- Action execution

**Layer 5 (Actions):** `actions/`
- Specific governance actions: auto_format_python, block_app_edits, block_edit_test, block_hooks_config, check_dependencies, complete_before_proceed, enforce_templates, inject_push_permission, inject_research_guidance, validate_governance
- Base action class in `_base.py`

**Layer 6 (Protocol):** `protocol.py`
- Response format definitions
- Hook response building functions

**Layer 7 (Audit):** `audit_log.py`
- Comprehensive logging of governance decisions
